9.4 Precedence rules as implemented
  Eligible = readable by role AND region matches (or GLOBAL) AND effective_date <= reference.
  Tests run in order (TASK.pdf 5.1), and the value decides as soon as one value remains:
    1. authority (policy, addendum, memo, handbook, calendar > faq, wiki, unknown)
    2. scope (region-specific > GLOBAL)
    3. recency (later effective_date)
  All three tests still run, so an agreeing but overridden document is not cited.
  If more than one distinct value remains: CONFLICT, both values and their documents returned,
  nothing picked.
  Upcoming change: a readable, region-applicable document effective after the reference date,
  which would win on its effective date and gives a different value from the current answer.
  Documents that would not win (e.g. v3 under a DE addendum) are not mentioned.
  No eligible document: NO_ANSWER.

11.6 Policy accuracy: mechanism and what is proven
  Mechanism:
    1. Retrieval: FAISS search over chunks, with predicates that remove unreadable, out-of-region and
       not-yet-in-effect chunks before ranking (in-effect set), and a separate upcoming set.
    2. Grouping by topic: the MODEL returns rules {topic, value, chunk_id}. Code normalises the topic
       (lower-case, punctuation removed) and groups rules with the same normalised topic. This is the
       weakest link: two documents that word a rule differently are not compared.
    3. Precedence: app/policy/precedence.py resolve() applies authority, then scope, then recency,
       stopping when one value remains; differing values -> CONFLICT (both reported, none chosen).
  Proven by deterministic tests (not model quality):
    - Contradictory values with a scripted provider: sick leave IN -> 12 (v2 beats FAQ on authority),
      DE -> 30 (addendum wins on scope), 2025 -> 10 with v2 reported as an upcoming change;
      accrual IN -> upcoming v3 mentioned, DE -> v3 not mentioned; synthetic conflict -> both reported.
  NOT proven:
    - Whether any live model groups topics and extracts values correctly. The mock provider never
      produces rules, so the mock is NOT evidence of answer quality. In the live run the mock quoted the
      superseded 2025 sick-leave passage (see 11.7 P1).
